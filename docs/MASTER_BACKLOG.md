## Convenzioni

- Review PO recepita (U03): modello Hub/epiche/workflow/protocollo approvati; pubblicazione/attivazione remote non autorizzate. PB-003 è candidato principale al planning, resta BACKLOG e non READY. Nessuna capacità o implementazione impegnata.
- PB-001–051 conservano ID e perimetro dell'inventario del PO (U01/U02); l'inclusione approva la direzione, non ogni soluzione né l'avvio di sviluppo. Dove le fonti mantengono EXPLORATORY, prevale quel grado di decisione.
- Classificazione riconciliazione: NEW = nuovo rispetto al corpus storico; EXISTING = equivalente documentato; DONE = esattamente già disponibile; DEPRECATED = scartato; EXPLORATORY = idea senza impegno; DUPLICATE = stesso risultato, rinvio canonico. Non è il lifecycle.
- Lifecycle e Decision sono separati. Implementation descrive il perimetro intero: PARTIAL può comprendere componenti rilasciati e residui futuri. Nessun PB parzialmente realizzato è chiuso come DONE.
- Priorità **proposte**, non validate: P0 incidente/integrità attivo; P1 prerequisito o problema concreto; P2 valore successivo; P3 ipotesi differibile. Nessun P0 riscontrato con questa ricognizione documentale. BACKLOG non significa READY.
- AC nelle righe sono criteri candidati, da rendere eseguibili nello scope della singola Issue prima del READY. `—` = nessun prerequisito noto, non promessa di indipendenza assoluta.
- Release Evidence: righe PARTIAL con fonti runtime/Git = **RELEASED per la sola parte presente**, sulla baseline fornita dal PO; residuo NOT RELEASED. NOT IMPLEMENTED funzionale = NOT RELEASED; per artefatti documentali accettati dello Sprint 0 Release Evidence = N/A, senza confondere accettazione, pubblicazione e attivazione. Nessun nuovo VERIFIED production/device in questa sessione.
- Dimensione stimata dei contenitori: Epic = XL, Spike = S/M, Feature = M/L da raffinare, Task = S/M. Non usare queste fasce per impegnare uno sprint; stime circoscritte nel Hub.
- Fonti S/C/G/U e decisioni sono risolte nel [Product Hub](PRODUCT_HUB.md#registro-delle-fonti). Epica determinata dal gruppo di ID sotto.

Decisione PO successiva U04 recepita nei soli PB-001/002/006/025: effetti contestuali Saga, review legacy mirata, revisione organica UX/UI e recupero Oscar. Priorità invariate; PB-003 resta candidato principale Sprint 1. Approvazione del refinement non equivale a READY o sviluppo autorizzato.
